## ⚠️ Telemetry changes — what users will notice after upgrading

**cdktn no longer sends any data to HashiCorp.** The checkpoint
telemetry transport (`checkpoint-api.hashicorp.com`) has been removed
entirely. Usage analytics now go to the project's own Sentry, and only
when enabled (see below).

**New `sendUsageTelemetry` flag in `cdktf.json`.** It controls usage
analytics independently of `sendCrashReports`. Everything that is
collected is listed below.

### What is collected (when usage telemetry is enabled and the build has a DSN)

Every usage metric carries: the **command**, whether the run is in **CI**
(the provider's name, or `false`), the **OS and architecture**, which
**binary** is installed (`terraform`, `opentofu`, `unknown`, `missing`)
and its release version when the product is recognised, the
**target versions** the project declares (or the CLI's defaults) plus
whether they were declared and whether binary validation is on, and the
project **language**.

Per command, a handful of counts and enumerated values: the synth
origin; the `init` **template** name (a built-in name, or the literal
`remote` for anything else) and whether it was remote; the number of
providers and modules generated by `get` or added by `init`; the
number of modules, providers and converted lines reported by `convert`;
the `watch` event.

Per synthesized stack (synth/diff/deploy/destroy): the **backend kind**
(one of Terraform's built-in kinds, else `other`), whether a
cloud/remote block is present, the **cdktn library version**, and the
**number** of overrides, imports and moves; one item per overridden
**resource type**; one item per **required provider** — public-registry
`namespace/type` only, with its version constraint and whether the
binding is generated or prebuilt; and a count of stacks that failed.

Per error: the **class** of the error (`Usage`, `External`, `Internal`,
`unexpected`) and the command it happened in.

Stamped by the Sentry SDK itself: a **random, persistent user id** kept
in `~/.cdktf/config.json` (delete the file and a new one is generated),
the **release** (`cdktn-cli-<version>`, which is how the CLI version is
known), a fixed environment `production`, the SDK name and version, the
fixed `server.address` `cdktn-cli`, a random per-process trace id and
the emission timestamp, and one session record per process carrying the
Node **major** version. Crash reports (a separate consent) additionally
carry the `projectId` from `cdktf.json`.

### What is never sent

Stack names; resource ids and addresses (imports and moves are counts
only); file paths and the working directory; the machine hostname or
username; private-registry hosts and organizations (reduced to
`private-registry`); module URLs and paths (reduced to `local`, `git`,
`private-registry` or `other`); remote template URLs (reduced to
`remote`); error messages and error context; any of your code; the
values of `SENTRY_*` environment variables. Tests assert these against
the raw envelope bytes, and CI asserts them on every build against a
local sink using deliberate leak markers.

**One-time interactive prompt on upgrade.** On the first run in an
interactive terminal (TTY, not CI), existing projects whose `cdktf.json`
lacks `sendUsageTelemetry` are asked once and the answer is persisted.
You may **also** be asked about crash reporting if `sendCrashReports`
is missing from your `cdktf.json`: that prompt existed before but never
fired due to a bug (a missing key was silently treated as "no"); it now
works as originally intended.

**Non-interactive runs (CI, piped) are unchanged.** No prompts; usage
telemetry stays on by default (as it always was, now routed to Sentry
instead of HashiCorp) and crash reporting stays off by default.

**`CHECKPOINT_DISABLE` keeps working.** It still disables usage
telemetry everywhere and still does not affect crash reporting. Telemetry
is also fully inert when the build has no Sentry DSN (e.g. self-built
binaries).

| Situation | Before | After |
|---|---|---|
| Usage data recipient | HashiCorp checkpoint API | Project's own Sentry |
| `sendUsageTelemetry` unset, interactive | sent silently (no prompt existed) | prompted once, choice saved |
| `sendUsageTelemetry` unset, CI/non-interactive | sent | sent (to Sentry) |
| `CHECKPOINT_DISABLE` set | no usage data | no usage data |
| `sendCrashReports` missing, interactive | treated as "no" (prompt was broken) | prompted once, choice saved |
| Machine hostname in crash reports | sent (Sentry default) | scrubbed (`serverName: cdktn-cli`) |
| Per-stack usage data | backend, provider and override details posted to HashiCorp | the same shape, reduced to enumerated values and counts, sent to the project's Sentry |
| Errors built by the CLI | `{type, message, context}` posted to HashiCorp | counted by type and command only — no message, no context |
